# BC카드 소비데이터: 데이터 감사·재분석·진단 사례·최종 보고서 작성

## 0. 역할과 목표

너는 이 프로젝트의 데이터 분석가이자 독립적인 검증자다.
기존 보고서를 요약하거나 가설을 추가하는 데서 끝내지 말고,
실제 프로젝트 파일을 확인하고 코드를 실행하여 결과를 검증하라.

현재 주제안:
「같은 매출 변화, 다른 처방」
BC카드 소비구조 분해 기반 상권 문제진단 및 맞춤형 개선안 제안.

핵심 질문:
“매출 변화가 비슷한 지역·업종이라도 결제건수, 건당 결제금액,
소비자 구성, 점포공급을 나눠 보면 먼저 점검할 문제가 달라지는가?”

이번 과업에서 답할 것:
1. 현재 무엇을 실제로 보유하고 있으며, 무엇은 보고서에만 언급돼 있는가?
2. 기존 결과 중 무엇이 재현되고, 무엇은 수정하거나 판단을 유보해야 하는가?
3. 기존 외부데이터는 어디에 필요하며, 누락·매핑·시차 때문에 어디에는 부적합한가?
4. 남은 설명을 구분하기 위해 어떤 데이터를 추가 확보해야 하는가?
5. 추가 자료가 진단을 어떻게 바꾸며, 어떤 개선 후보를 검토하게 만드는가?
6. 이 방법은 일반적인 지표 조회·분석보다 무엇을 추가로 제공하는가?

기존 주제를 증명하기 위해 유리한 지역·기간·임계값을 골라서는 안 된다.
성장착시는 보조 진단 도구다. 원래 정의가 희소하면 그대로 보고하고,
정의를 넓혀 발생률을 부풀리지 않는다.

주제가 충분히 뒷받침되지 않으면 그 결론도 허용한다.
분석 결과와 가설, 해석, 개선안, 향후 검증계획을 명확히 구분한다.


## 1. 실행 순서와 중단 조건

다음 순서로 실행한다.

A. 파일·데이터 현황 조사
B. BC 및 기존 외부데이터 품질 감사
C. 기존 결과 재현 및 수정
D. 외부데이터 유지·제한사용·제외 판정
E. 남은 질문에 필요한 데이터만 추가 수집
F. 소비구조 분해와 지역·업종 비교
G. 대표 진단 사례와 개선 후보 작성
H. 방법론 비교검증 및 최종 보고서 작성

A~D를 하기 전에 새로운 대규모 데이터 수집이나 모델 학습부터 하지 않는다.
단계별 산출물을 저장한 뒤 다음 단계로 진행한다.

필수 원자료가 없으면 해당 분석을 BLOCKED로 남기고 독립적으로 가능한 부분은 계속한다.
보고서의 수치를 복사해 새로 계산한 결과처럼 사용하지 않는다.
모든 작업을 못 마쳤다면 완료·미완료·차단 항목과 이유를 구분한다.


## 2. 기존 결과: 재현해야 할 주장 목록

다음은 이전 보고서의 주장이지, 검증된 정답이 아니다.
먼저 해당 보고서·코드·CSV의 존재와 계산 정의를 확인한다.

- BC 기간: 2026년 1~6월. 기존 보고서상 지역 255개, 업종 11개.
- 공통 7개 업종 분석: 254개 지역 중 231개에서 건당 평균 결제금액 하락.
- 그중 220개에서 OLS·Theil–Sen·전후반 비교의 방향 일치.
- 건단가 변화의 절대기여 비중 중앙값: 업종 내부 63.7%, 업종 구성 36.3%.
- 251개 지역 중 203개에서 60세 이상 결제건수 비중 증가가 주민 비중 증가보다 빠름.
- 그 차이의 중앙값: +0.151%p/월.
- 연령 HHI와 AMT 잔차변동성: Spearman rho=0.419.
- HIGH로 분류했던 점포 매핑 509개 지역×업종 중:
  · 매출 증가·점포 증가·점포당 BC 이용금액 감소: 22개, 세 방법 일치 2개.
  · 매출 감소·점포 증가: 121개, 세 방법 일치 54개.
- HIGH 매핑은 중국음식·제과점이며, HIGH 판정 근거 자체도 재검토 대상.
- 7개 공통업종 CNT 집중도 증가: 207/254개.
- 폐업률·순점포변화 지역 교차검증 R²: 각각 약 0.020, 0.016.
- 관광 방문자 원자료는 미확보로 기록됨.
- 공간분석은 공식 경계가 아니라 제과점 시설좌표 기반 KNN 근사였음.

특히 확인할 것:
- 63.7%는 전국 총액의 분해비율인지, 지역별 절대기여 비중의 중앙값인지 구분.
- 집단별 기여율 중앙값을 합해 전국 성장기여율처럼 해석하지 않을 것.
- 세 가지 분석방법은 같은 6개월을 재사용한 강건성 검사이지 독립 표본 검증이 아님.
- 기존 보고서의 STRONG/MODERATE 등급을 그대로 계승하지 말 것.

## 4. BC 원자료 품질 감사

다음을 점검하고 결과를 표로 남긴다.

1) 정의와 단위
- AMT가 실제 금액인지, 금액 단위가 무엇인지, CNT가 무엇을 집계하는지.
- 지역이 가맹점 소재지 기준인지 다른 기준인지 공식 설명 확인.
- 월별 집계범위·자료제공 기준·비식별 처리·가중치 여부.
- 코드북으로 성별·외국인·법인·연령·업종 코드를 확인.
- 공식 정의를 확보하지 못한 부분은 UNVERIFIED로 유지.

2) 키와 중복
- 월×시도×시군구×업종×성별×연령 키의 중복.
- 이름이 같은 시군구, 시와 하위 구의 중복 집계, 행정구역 코드 변경.
- 소계·전체 행이 상세행에 섞여 중복 합산되지 않는지.
- 중복 제거는 이유가 확인된 경우에만 실행하고 변경내역 저장.

3) 관측 구성
- 월별 행수·지역수·업종수·고객세그먼트 수.
- 6개월 완전관측 지역×업종과 불완전관측 조합.
- 지역×업종이 완전관측이어도 내부 연령·성별 셀이 월별로 달라지는지.
- 전 기간 공통 셀과 새로 나타난/사라진 셀의 AMT·CNT 비중.
- 셀 관측범위 변화가 성장·집중도 지표에 영향을 주는지.

4) 값의 이상
- AMT/CNT 0·음수·취소 가능성·단위 오류·극단값.
- 최소 CNT 등 제공 기준의 흔적. 공식 근거 없이 비식별 규칙을 확정하지 말 것.
- 미관측, 비공개/억제, 해당 업종 없음, 수집 실패를 가능한 한 구분.
- 미관측을 일괄 0으로 바꾸지 않는다.

5) 공간·기간 정합성
- 2026년 상반기 행정구역 기준표와 매핑 이력.
- 현재 주소를 과거 경계로 변환한 근거와 미해결 지역.
- 상위지역으로 합쳐 해결할 경우 BC와 외부자료를 모두 같은 단위로 재집계.
- 과거 상위지역 값을 현재 하위지역에 임의 배분하지 않는다.

분석 표본을 구분:
A. 가능한 전체 BC 관측범위
B. 6개월 완전관측 패널
C. 공통 업종 패널: 정확한 업종명·코드·제외 사유 명시
D. 낮은 거래량 제외·고정 고객세그먼트 등 민감도 표본

어떤 결과든 사용한 표본과 전체 BC 대비 AMT/CNT 포괄률을 표시한다.


## 5. 기존 외부데이터의 실제 필요성을 감사하라

데이터가 많다는 이유로 유지하지 말고, 누락이 있다는 이유만으로 폐기하지도 않는다.
데이터셋 전체뿐 아니라 개별 변수·용도별로 적합성을 판정한다.

### 5-1. 공통 점검표

각 자료에 대해 다음을 작성:
- 어떤 질문을 해결하는가?
- 실제 단위·기간이 BC와 맞는가?
- 공식적 업종·지역 대응인가, 분석자의 근사 매핑인가?
- 결측률과 미매칭률은 각각 얼마인가?
- 누락이 특정 지역규모·군/도시·업종·성장률에 집중되는가?
- 동일 표본에서 이 자료를 넣기 전후 무엇을 추가로 알게 되는가?
- 현재 용도에 필요 없는 변수나 중복 정보는 무엇인가?

coverage는 최소한 다음을 모두 보고:
1. 전체 BC 대상 대비 지역×업종×월 연결률.
2. 해당 자료가 원래 설명 가능한 업종·지역 범위 내 연결률.
3. 6개월 연속 유효한 분석단위 비중.
4. 연결된 BC AMT / 해당 분석범위 전체 BC AMT.
5. 연결된 BC CNT / 해당 분석범위 전체 BC CNT.

외부자료를 고객세그먼트 행에 결합하면서 중복 생성한 행수로 coverage를 계산하지 않는다.
조인 전후 행수·키·AMT/CNT 총합을 검사하고 many-to-many 중복을 방지한다.

### 5-2. 주민등록 연령별 인구

- 2026년 1~6월 월별 실제값, 행정경계, 연령구간 일치 여부 확인.
- 주민 인구와 지역 내 결제자 모집단은 다를 수 있음을 명시.
- 지역 결제액/주민수는 ‘주민 1인당 실제 지출’이 아니라 지역 결제강도 대리지표.
- BC의 연령 관측범위와 인구 분모의 범위가 다르면 차이를 보고.
- 소비연령 비중과 주민연령 비중의 차이는 ‘인구효과를 인과적으로 제거한 값’이 아님.
- 60세 이상 증가를 위험·소비기반 붕괴라고 자동 판정하지 않는다.

### 5-3. CPI

- 공표 지역·품목·월·기준연도와 BC 업종 대응을 점검.
- BC 업종과 CPI 품목의 매핑을 근거와 함께 재평가.
- 여러 품목을 파는 편의점·슈퍼 등을 단일 식품물가와 완전히 같다고 처리하지 않는다.
- 실질화는 AMT / (CPI_t / 기준시점 CPI)처럼 기준을 명시.
- 전국/광역 물가를 시군구 가격자료처럼 표시하지 않는다.
- 큰 결과를 만들지 않아도 명목·실질 구분을 위한 적절한 통제라면 유지 가능.

### 5-4. LOCALDATA 및 소진공 점포자료

이 부분은 특별히 엄격하게 확인한다.

- 인허가 관리번호 수와 물리적 점포 수를 구분.
- 동일 장소의 복수 인허가, 다른 파일 간 중복, 재개업·이전·휴업 처리 확인.
- 인허가일이 실제 개업일과 같다는 가정, 폐업일의 정확도·결측을 명시.
- 현재 영업상태만으로 1~6월 과거 영업점포를 복원하지 않는다.
- 현재 생존점포만 담긴 파일로 과거 전체 점포수를 만들지 않는다.
- 최신 스냅샷 하나만 있으면 공급의 현재 수준은 볼 수 있어도 월별 공급증가는 계산하지 않는다.
- 두 스냅샷이 있으면 그 시점 간 변화만 계산하며 중간 월을 관측값처럼 보간하지 않는다.
- 인허가 이력으로 재구성할 때는 월말 영업점포, 월평균 영업점포/노출일수의 정의를 명시.
- 기초 점포+개업-폐업+행정/재분류 조정=기말 점포의 회계적 일치 여부 확인.
- BC 업종과 외부 업종의 대응표·신뢰도·미포함/중복 범위를 작성.
- 기존 HIGH 매핑도 BC 정의와의 일치를 검토한 뒤에만 유지.

AMT/외부점포수는 ‘BC 집계 이용금액/대응 인허가 점포수’ 대리지표다.
BC 가맹점과 전체 인허가점포의 모집단이 동일함을 입증하지 못했다면
개별 점포 평균매출·실제 이익·경쟁강도로 단정하지 않는다.

### 5-5. 관광 방문자

- 로그인 안내나 뉴스기사만 있는지, 실제 월별 원자료가 있는지 구분.
- 방문자 정의, 중복방문, 주민 제외 여부, 통신사 추정범위 확인.
- 외국인 카드거래를 관광객 전체 또는 외국인 관광객과 동일시하지 않는다.
- 관광소비 자료가 BC 등 같은 카드자료에서 파생됐다면 독립 검증으로 표시하지 않는다.
- 방문자료가 없으면 주민/방문 소비를 실제로 분리했다고 주장하지 않는다.

### 5-6. 임대료·공실·공간자료

- 실제 파일이 없으면 기존 보유자료가 아닌 수집 후보로 표시.
- 조사대상·부동산 유형·지역경계·공표주기를 확인.
- 상권별 임대료를 같은 이름의 시군구 전체값으로 대입하지 않는다.
- 1·2분기만 있다면 BC도 대응 분기로 합쳐 비교. 2개 시점을 긴 시계열처럼 분석하지 않는다.
- 분기값을 3개 월에 복제해 독립 표본 수를 늘리지 않는다.
- 공간단위가 맞지 않으면 전국 주분석에서 제외하고 명시적인 사례자료로만 사용.
- 시설좌표 중심점 KNN과 공식 경계 인접관계를 구분한다.

### 5-7. 최종 데이터 판정

각 데이터·변수·사용범위에 아래 중 하나를 부여:
CORE: 주분석에 적합하고 설명에 필요함.
CONTROL: 주요 발견을 만들지는 않지만 비교의 타당성에 필요함.
MODULE_ONLY: 고품질이나 일부 업종·지역·기간에만 적합함.
CASE_ONLY: 전국 결론이 아닌 대표사례 보완에만 적합함.
HOLD: 미확보·정의 불명·기간 불일치 등으로 현재 판단 불가.
DROP_FROM_ANALYSIS: 오류·중복·부적합·추가 정보 부족으로 분석에서 제외.

원본은 삭제하지 않고 분석 채택 여부만 바꾼다.
단일 임의 결측률 기준으로 전부 버리지 않는다.
반대로 2개 업종 결과를 11개 업종의 전국 결론으로 확대하지 않는다.
모든 외부자료의 교집합만 남겨 전체 표본이 축소되지 않도록 모듈별 분석을 유지한다.


## 6. 기존 분석의 계산·해석 감사

다음을 확인한 뒤 결과를 재사용한다.

- CNT=결제건수. 고객수·방문자수·재방문 빈도로 바꾸어 표현하지 않는다.
- AMT/CNT=건당 평균 결제금액. 상품가격·이익과 구분한다.
- 6개월 회귀에는 관측점 6개와 시작~종료 간격 5개가 있음.
- 실제 1월→6월 변화, 회귀 적합 변화, 월성장률, %p 변화를 혼동하지 않는다.
- 동일 관측월·가중치에서 log AMT slope = log CNT slope + log 건단가 slope를 확인.
- exp(beta)-1로 변환한 성장률들을 단순 더해 항등식처럼 쓰지 않는다.
- 달력일수 보정은 가능하지만 실제 점포 영업일수라고 표현하지 않는다.
- 전국 동일업종 추세 대비 상대 부진과 절대 감소를 분리.
- 가능하면 본 지역을 제외한 전국 동일업종 기준도 민감도 검사.
- 추세가 0에 가까운 경우 중립·불확실 구간을 두고 작은 부호차이로 위험판정하지 않는다.
- 총 성장률이 0 부근이면 기여율 대신 원단위 변화·로그기여·구성비를 보고.
- HHI와 Entropy, AMT·CNT·건단가, 수요공급Gap·점포당지표의 수학적 중복 확인.
- 같은 산식에서 나온 변수끼리의 상관은 독립적인 외부 검증이 아니다.
- 기초수준과 성장률에 같은 기간값이 들어가 생기는 수학적 결합·평균회귀를 검토.
- 6개 월의 잔차변동성은 불확실성이 큼. 지역규모·업종구성·관측누락을 함께 검토.
- 점포수/폐업을 함께 넣고 같은 기간 순점포변화를 맞히는 등 목표변수 누출 점검.
- 군집 입력에 폐업률이 있었다면 군집별 폐업률 차이를 독립 검증으로 쓰지 않는다.

통계검정은 필요한 질문에만 사용한다.
지역×업종의 반복·공간 의존성을 고려하며 수백만 거래를 독립 표본처럼 취급하지 않는다.
검정군별 FDR, 효과크기, 불확실성, 표본수·실제 규모를 함께 보고한다.
재탐색한 동일 자료의 결과를 새 독립 검증처럼 포장하지 않는다.


## 7. 새로운 외부데이터는 ‘해결할 질문’부터 정하고 수집하라

기존 감사 후 unresolved_questions.csv 작성:
질문 / BC로 확인한 사실 / 가능한 다른 설명 / 추가로 필요한 변수 /
기존 자료 재사용 가능 여부 / 후보 공식 출처 / 요구 기간·단위 /
수집 우선순위 / 확보되면 달라질 판단 / 실패 시 대안.

예시:
- 결제건수 감소가 업종 공통인지 지역 방문 흐름과 연결되는지:
  → 동일업종·타업종 BC 비교 후 필요한 지역의 월별 방문자료.
- 공급 증가가 실제인지 자료 갱신·재분류인지:
  → 과거 점포 스냅샷·인허가 이력·업종/경계 변경내역.
- 군 지역 급변이 결제수단이나 특정 시점 변화와 겹치는지:
  → 공식 정책·지역화폐·행사 일정 및 BC 데이터 포함범위 확인.
- 건단가 변화가 개별 가게의 할인·상품구성 때문인지:
  → 공개자료의 한계를 명시하고 점포 입력/POS 필요 항목으로 분리.
- 임대환경이 진단을 바꾸는지:
  → 공간·기간이 맞는 공식 임대료·공실자료가 있는 사례에서만 확인.

공식 기관 원자료를 우선하고, 검색 결과·기사의 집계값을 월별 원자료로 만들어내지 않는다.
다운로드한 파일이 실제 CSV/ZIP인지 HTML 오류화면인지 검증한다.
로그인·유료·API키·네트워크 제한이 있으면 이를 우회하지 않는다.
합리적인 경로 확인 후 차단된 자료는 HOLD로 기록하고 다른 분석을 진행한다.
새 자료가 없을 때 과거 연도 값을 2026년 자료로 대체하지 않는다.
과거 자료는 별도 역사적 맥락으로만 사용한다.

새로 수집한 자료도 반드시 5절의 품질·가치 평가를 통과해야 한다.
많이 수집한 것이 성과가 아니라 필요한 질문을 해결한 것이 성과다.


## 8. 핵심 재분석: 어떤 조건에서 진단이 달라지는가?

기존 H1~H18을 무조건 전부 다시 확장하지 말고 아래 질문에 집중한다.

Q1. BC의 소비변화는 관측범위·일수·업종구성을 맞춰도 남는가?
- 전체/완전패널/공통업종/고정세그먼트 결과 비교.
- 일반 추세와 상대 추세, OLS·Theil–Sen·전후반 비교 병기.
- 전국 대표 현상과 작은 부분표본 현상을 분리.

Q2. 건단가 변화는 업종 내부 변화와 업종 구성변화 중 어디에 연결되는가?
- q_t = Σ_i w_it * q_it, w는 CNT 비중, q는 업종 건단가.
- 비교기간은 월별 및 전반/후반으로 설정. 분기 q는 합계AMT/합계CNT로 계산.
- 두 시점의 정확한 대칭 분해를 사용 가능:
  Δq = Σ_i mean(w_i)*Δq_i + Σ_i mean(q_i)*Δw_i.
- 동일한 고정 업종집합에서 항등식·분해 잔차를 검사.
- ‘업종 내부’에도 고객·상품·점포 믹스가 남으므로 순수 가격효과로 해석하지 않는다.

Q3. 같은 업종에서 비슷한 AMT 변화가 서로 다른 점검 과제로 이어지는가?
- 같은 업종, 비슷한 초기 거래규모, 비슷한 AMT 추세의 지역을 매칭.
- 유사성 허용범위는 결과 사례를 고르기 전에 config에 명시하고 민감도 검사.
- CNT·건단가·연령구성·공급 변화의 실질적인 차이를 비교.
- 구조 차이 자체가 생기는 것은 당연할 수 있으므로 차이의 크기·강건성을 확인.
- 가능 사례 전체의 수와 분모를 제시한 뒤 대표 사례를 선택.
- 상승 지역만 보지 말고 정체·감소 지역도 포함.

Q4. 지역 전체 추세를 해당 업종에 그대로 적용하면 판단이 달라지는가?
- 동일 고정 업종범위의 지역총량과 목표업종 추세를 비교.
- 총량 증가·목표업종 감소, 총량 감소·목표업종 증가 등을 별도 정의.
- 부호만 아닌 실제 변화폭·거래규모·강건성도 보고.
- 이를 기존 서비스의 오류 발생률이라고 부르지 않는다.

Q5. 외부자료를 추가하면 어떤 설명이 새로 확인되거나 약해지는가?
- BC만 / BC+인구 / BC+점포 / BC+기타 검증자료를 모듈별 비교.
- 각 비교는 반드시 동일 지역·업종·월의 교집합 표본에서 수행.
- 추가 정보를 넣은 결과와 표본이 바뀐 결과를 분리.
- 추가정보, 범위 제한, 불확실성 해소 여부를 기록.
- 자료를 넣어도 진단이 바뀌지 않거나 불확실성만 커지는 경우도 보고.
- 수요공급Gap과 점포당지표의 동치는 계산 검증이지 새로운 발견이 아님.

현재 자료로 검증 불가능한 설명은 NOT_TESTABLE로 남긴다.
지지되지 않음과 자료가 없어 검증하지 못함을 구분한다.


## 9. 대표 사례 3~5쌍: 진단과 개선안을 연결

견고한 사례가 부족하면 수를 줄이고 이유를 보고한다.
유명 지역이나 극단값만 임의로 선택하지 않는다.
반드시 원자료 행/집계키와 계산표로 추적 가능하게 한다.

각 사례 카드:
1. 지역·업종·기간·거래규모·자료 연결률.
2. 표면 관측: AMT 추세와 불확실성.
3. 분해: CNT·건단가·업종/연령구성·공급 변화.
4. 외부자료가 추가한 사실과 자료의 한계.
5. 데이터가 지지하는 설명 후보.
6. 여전히 구분되지 않는 대안 설명.
7. 점주에게 먼저 확인할 질문과 그 질문이 판단을 바꾸는 이유.
8. 확인 결과별 조건부 개선 후보.
9. 개선안의 실행 제약·확인 지표·중단 조건.
10. 근거가 부족하여 현재는 권하지 않는 단정/행동.

개선안은 지역 데이터에서 개별 점포의 정답을 만들어내는 방식이 아니다.
예: 건수 감소를 보았다고 바로 광고비 증액을 추천하지 않는다.
점포의 영업일·주문건수·판매구성 등을 확인한 뒤 어떤 대응을 시험할지 구분한다.

가격·광고·메뉴·운영 변경의 실제 효과를 측정하지 않았다면 개선 ‘후보’라고 적는다.
실제 점포자료가 없는 가상 상담은 명확히 가상이라고 표시하고,
발생률·원인검증·사업효과의 증거에 포함하지 않는다.


## 10. 기존 방식 대비 추가 가치 검증

“기존 서비스는 매출만 본다”, “ML은 설명 불가능하다”를 전제로 삼지 않는다.
실제 경쟁 서비스나 수상작의 방법을 언급하려면 공식 원문으로 확인하고
공개되지 않은 기능은 모른다고 적는다.

기본 비교는 외부 팀의 성능을 추정하는 대신 내부 통제실험으로 한다.

B0. 일반 BC 지표표:
AMT·CNT·건단가·고객구성·업종 추세를 충분히 제공한다.
AMT 하나만 주는 과도하게 약한 비교기준을 만들지 않는다.

B1. B0와 동일 원자료+소비구조 분해:
기여도·within/mix·총량/업종 차이·근거/미확인 구분.
B1-B0는 같은 원자료에서 분석·제시 방식의 추가 가치를 평가한다.

B2. B1+품질감사를 통과한 외부 맥락.
B2-B1는 동일 표본에서 외부자료 추가의 가치를 평가한다.

B0E. B2와 같은 BC·외부 원자료를 일반 지표표/체크리스트로 제공.
B2-B0E는 데이터를 더 많이 준 효과가 아니라 분해·진단 절차의 효과를 평가한다.

기본 체크리스트가 이미 해결하는 것은 우리만의 장점이라고 주장하지 않는다.
추가 분석을 했다는 사실과 실제 의사결정이 개선됐다는 사실을 구분한다.

LLM 비교를 수행할 환경과 허가가 있으면 모델·설정·점포 Context·출력분량을 고정한다.
분석 효과 비교에서는 같은 질문과 같은 점포정보를 제공한다.
대화형 추가질문의 효과는 별도 비교로 분리한다.

평가 항목:
- 수치·출처 일치율.
- 자료로 뒷받침되지 않는 원인 단정 비율.
- 핵심 누락정보를 확인하는 질문의 적절성.
- 진단과 개선 후보의 논리적 연결.
- 불확실성·적용범위 표시.
- 운영상 실행가능성은 실제 점주/전문가 평가가 있을 때만 평가 완료로 표시.

자동 검증 가능한 항목과 사람 평가가 필요한 항목을 구분한다.
분해 규칙만 적용한 비LLM 체크리스트도 비교하여 LLM이 실제로 추가한 역할을 구분한다.
전문가가 없으면 전문가 평가점수를 만들지 않는다.
LLM 자기평가를 객관적 정답으로 사용하지 않는다.
API·예산·평가자가 없으면 평가용 자료와 실행 절차까지만 만들고 NOT_RUN으로 보고한다.
같은 개선안이 적절한 반례도 포함한다. 처방을 무조건 다르게 만드는 것이 목표가 아니다.


## 11. 최종 보고서 구성

한국어 Markdown 보고서로 작성하되, 간결한 본문과 상세 부록으로 나눈다.
표·그림은 실제 저장한 결과에서 생성하고 깨진 링크·존재하지 않는 그림을 남기지 않는다.

본문:
1. 요약: 무엇이 남았고, 무엇을 버렸으며, 주제는 어디까지 방어 가능한가?
2. 연구질문·분석범위·용어 정의.
3. 데이터 보유현황과 품질 감사.
4. 기존 결과 재현 및 수정사항.
5. 외부데이터별 유지·통제·제한사용·보류·제외 판단과 이유.
6. 추가 수집 필요성·실제 확보결과·실패기록.
7. 핵심 소비구조 분석과 강건성.
8. 같은 매출 변화의 대표 사례 비교와 조건부 개선 후보.
9. 일반 지표분석 대비 추가 정보와 비교검증 결과/미실행 사항.
10. 결론: 왜 필요한가, 실제 입증된 장점은 무엇인가, 아직 무엇이 미확인인가?

반드시 구분:
- 관측된 사실
- 수학적 항등식에 따른 분해
- 탐색적 상관·설명 후보
- 외부자료로 추가 확인된 사실
- 현장검증이 필요한 가설
- 제안한 개선 후보
- 실제 측정한 개선효과

보고서의 최종 질문:
“이 분석 덕분에 기존 자료만 볼 때보다 무엇을 더 알게 되었고,
어떤 성급한 판단을 피하거나 어떤 점검을 먼저 할 수 있게 되었는가?”

그 답이 약하면 새로운 지수·군집·LLM 서술로 덮지 말고 약하다고 결론낸다.
실제 사업성과 개선을 측정하지 않았으면 폐업 감소·매출 증대 효과를 수치로 쓰지 않는다.


## 12. 재현 산출물과 완료 기준

run_id별로 다음을 저장한다.

- README: 실제 실행한 명령, 환경, 실행순서, 완료/차단 상태.
- data_inventory.csv
- bc_quality_audit.csv
- coverage_by_dataset.csv
- missingness_bias.csv
- external_data_decisions.csv
- industry_mapping.csv / geography_mapping.csv
- claim_reproduction.csv
- unresolved_questions.csv
- acquisition_log.csv / source_metadata.csv
- analysis_panel 또는 모듈별 정합 패널
- 핵심 결과·민감도·대표사례 CSV
- evidence_cards / 비교평가 자료 및 실제 평가결과
- figures/
- final_report.md
- 코드, 설정, 패키지 버전, seed, 원본 체크섬, 실행 로그.

내부 분석용 식별정보와 공개 보고서를 구분하고 비밀키를 저장하지 않는다.
원본자료는 수정하지 않는다. 분석 제외 자료도 삭제하지 않고 이유를 기록한다.

완료 점검:
[ ] 언급한 데이터는 실제 확보 여부가 표시돼 있다.
[ ] 기존 결과는 재현/수정/미재현/차단 상태로 분리돼 있다.
[ ] 모든 외부데이터는 용도·coverage·품질·최종 채택 판정이 있다.
[ ] 모든 주요 수치는 분모·단위·기간·표본범위·계산근거를 갖는다.
[ ] 데이터 결합 전후 중복·누락·총합을 검증했다.
[ ] 월별 자료가 없는 곳에 월별 변화값을 만들어 넣지 않았다.
[ ] 분석 표본 감소·업종 제한·결측 편향을 숨기지 않았다.
[ ] 대표 사례는 코드로 재선정·재계산할 수 있다.
[ ] 개선 후보와 실제 검증된 효과를 구분했다.
[ ] 주제가 약해지는 결과와 대안 설명도 포함했다.
[ ] 보고서에 등장하는 파일·그림·실행명령이 실제로 존재·동작한다.

최종 응답에서는 전체 보고서를 반복하지 말고 다음을 요약하라.
1. 재현된 핵심 결과.
2. 유지·제한사용·보류·제외할 외부데이터.
3. 추가로 꼭 필요한 데이터와 확보 상태.
4. 대표 사례에서 실제로 달라진 점검 순서.
5. 현재 주제의 방어 가능 범위와 미해결 문제.
6. 보고서·코드·결과 파일의 실제 경로.
